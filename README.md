# shadle.

A daily GLSL shader challenge. Start with a fragment shader, complete one marked expression, and match the target image in six submissions. The centered stacked layout attaches the Shadle header to the preview and editor card. The header and game center vertically together. Attempts and a Hints button share a compact row below; Hints opens a dismissible panel.

Run `npm run dev` and open the local URL printed by the server (port 4173, or the next free port). No installation or build step is required. Serve `dist/` with any static host. The app uses real WebGL fragment shaders; graphics acceleration must be available.

Typography comparisons are available at `/typography/index.html` on the same local server. It opens a full-screen HTML preview; `?option=01` through `?option=10` choose the starting option. A small floating control shows the current number and name, with **Next** cycling through all ten and wrapping to the first. Hover the name for font and size details. All use the same Square Mask puzzle and the original Space Grotesk logotype. Preview progress stays in memory and resets on reload. The main game's fonts and saved progress are independent. Preview fonts and their licenses are bundled under `dist/typography/fonts/`. Run `node scripts/build-typography-previews.mjs` to regenerate the HTML and preview app after workspace changes; `scripts/fetch-typography-fonts.ps1` fetches the public font assets when needed.

Each short starter includes its coordinates, colors, rendering, and one marked TODO. Complete a GLSL expression such as a distance, wave, blend, or tiling operation. Every line remains editable. The first three unsuccessful shader submissions each unlock one progressive hint: a concept, an expression, then the corrected statement. Available hints can be revealed on demand without using another attempt. Previews, compile errors, duplicate submissions, and successful submissions do not unlock hints. Revealed hints are capped at the number earned when restoring older saves. The TODO and its incomplete expression are highlighted in the gutter. The editor provides syntax highlighting, line numbers, indentation, and inline compiler errors. Preview runs automatically after a short pause, or immediately with Ctrl/Cmd + Enter. Submit with the button or Ctrl/Cmd + Shift + Enter. Only valid submissions consume attempts. Invalid drafts preserve the last valid output and save across reloads.

Ctrl/Cmd + S saves your shader draft to local browser storage and suppresses the browser's Save Page dialog while the page has focus. It does not submit an attempt. Drafts also save automatically as you type.

In the shader editor, Ctrl/Cmd + X cuts the entire current line when nothing is selected, including its following line break when present. Selected text cuts normally. Cutting uses the browser's native clipboard and undo behavior, updates the saved draft and preview, and does not use an attempt. Completed puzzles remain read-only.

The **Uniform Reference** link beneath the editor buttons opens the GLSL functions and uniforms reference. Keyboard shortcuts stay beside it; the separate topic and description section beneath Hints is removed.

The preview header shows **SHADER PUZZLE #… / date**. A hatched file bar separates the preview images from the editor. The separate puzzle metadata section, repair brief, and Jump to TODO strip are removed. Daily, practice, and debug sessions share the same puzzle title format.

The main game uses typography option 10, **Big and clear**: Atkinson Hyperlegible for the interface, Fira Mono at 14px with 26px line spacing for code, and the original Space Grotesk logotype. Selected fonts and their licenses are bundled in `dist/fonts/`; `dist/typography.css` applies the chosen sizing.

For debugging, the top-right **Next puzzle** button advances one UTC calendar day from the current puzzle. It saves the current draft, loads that day's starter and saved practice progress, and labels the session as debug. Debug attempts use practice storage even when navigating onto today's date, keeping daily stats separate. **Back to today** returns to the daily puzzle with its original progress. Refreshing also returns to the daily puzzle.

Shaders use GLSL ES 1.00 with `void main()` and `gl_FragColor`. Declare `uniform vec2 u_resolution` for drawing-buffer dimensions and `uniform float u_time` for time, fixed at 0 for reproducible comparisons. Declared Shadertoy-style `iResolution` (vec3) and `iTime` (float) are also supported. Textures and external assets are not supplied.

Scoring compares actual RGBA render buffers at 96 × 96 using RGB pixel error and luminance edges. Source text is never used for matching; different programs producing the same image win. Attempts are a compact row of six boxes, each showing its attempt number and percentage close to the target. Click a submitted box to review its shader. At desktop sizes and taller mobile sizes, the stacked layout fits the viewport with shader source scrolling inside the editor. Shorter screens use normal page scrolling. The Hints button shows the unlocked count and highlights when an unrevealed hint is available. Its panel closes with Escape, the close button, or a click outside. Output stays on the left and Target on the right. The accepted tolerance is mean RGB error ≤ 0.008 (normalized 0–1) and relative edge error ≤ 0.08, displayed as an overall match of 98% or more.

Daily puzzles are deterministic and reset globally at midnight UTC. Eight beginner challenges cover linear gradients, circle masks, sine stripes, checkerboards, square masks, ring masks, and sine waves. Draft source, last valid output source, revealed hints, complete submitted shaders, sound preferences, and statistics are saved in browser local storage. The Puzzle Archive has separate practice progress. Attempt History shows compact score boxes; each submitted shader can be reviewed and reloaded. After a session, the reference implementation is available. Results can be shared without revealing source code. Guided progress uses its own storage key, preserving both earlier versions' saved data. This client-side prototype does not provide competitive anti-cheat protection.

Interface copy and shader examples use conventional graphics and programming terminology: fragment shader, target image, output, normalized coordinates, interpolation, distance, mask, and reference implementation. Generated shaders use descriptive color identifiers such as `shapeColor`, `leftColor`, and `rightColor`. Recognized older built-in starters and solutions are updated on load; custom-edited shader source and comments are preserved.

Solving a puzzle or using all six attempts opens a result modal with attempt count, best match, hints used, and the score history. The workspace stays at its normal height. Close the modal to inspect the shader, then use **View result** in Attempt History to reopen it, including after reloading a completed puzzle. The reference solution links back to the result.

The result modal previews shareable text containing scores, puzzle date, daily/practice/debug mode, and hints used, without shader source. **Share result** opens the system share sheet when supported and falls back to copying the text. **Copy result** copies directly, with manual selection available if clipboard access is unavailable. Localhost URLs are omitted; public HTTPS deployments can include the site URL. Nothing is sent until the player chooses to share.

`npm test` checks daily generation, image-based scoring, spatial mismatches, sharing, streaks, safe highlighting, and indentation. `npm run check` validates JavaScript syntax.

Source files are in `dist/`: `index.html` (workspace), `styles.css` (responsive design), `typography.css` (selected font sizing), `game.js` (image scoring), `puzzles.js` (full daily programs), `renderer.js` (WebGL compilation and readback), `editor.js` (code editing), and `app.js` (interaction and persistence). Fonts and their licenses are bundled locally, with system fallbacks included. Development remains local; no publishing is required.
